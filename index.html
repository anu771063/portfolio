Naylor: redesigning a 100+ page site while preserving its search foundations

Naylor needed a modern redesign that kept its established URL structure and SEO metadata intact, migrated the blog, and made a large site easier to navigate and maintain.

Visit Naylor →

My role

I built the pages in Elementor from Adobe XD designs, added custom code where the builder fell short, updated page copy, handled on-page SEO, and communicated directly with the client. The client’s designers created the visual direction.

Navigation decision

I built the mega menu with custom code rather than adding a menu plugin or relying on Elementor Pro. That gave the 100+ page site tailored navigation without another plugin dependency.

Build approach

I kept Elementor as the day-to-day editing tool for the client’s team and reserved custom code for features the builder could not handle cleanly.

SEO and migration

I preserved the existing URL structure, meta titles, descriptions, and other SEO tags while rebuilding the site and migrating the blog content.

Outcome

The 100+ page redesign launched with the custom mega menu and the existing URL and metadata structure retained.

Lynkora · WordPress plugin
WordPress plugin · Internal linking

Lynkora

Challenge

Site owners can miss orphaned pages, broken links, dead ends, and content that is difficult for visitors to reach.

My role & approach

I built Lynkora to map links across posts, pages, menus, widgets, and block templates, then explain issues and suggest practical fixes.

Key decisions

Changes happen only when an editor chooses a fix, and WordPress revisions preserve a way to undo content edits. The plugin also tracks old page addresses and redirects them when appropriate.

Outcome

A published WordPress.org plugin with link health reports, guided fixes, scan history, CSV exports, and optional WP-CLI reports.

Hooktrail

Hook Debugging

I built a WordPress debugging plugin that shows which hooks ran on a page, which plugin or theme attached each one, and what each one cost or changed.

What I built

  • A timeline of every action and filter, grouped by load stage, with timing and the plugin behind each callback.
  • A trace view that shows a filter's value before and after each callback, to find which plugin changed it.
  • An issues report for plugin conflicts, repeated queries, and slow hooks.
  • WP-CLI commands to record pages and compare maps in deploy checks, with no external services.
